Clue order notes for a basketball player guessing game

I have been testing a small basketball player guessing game in the browser. The difficult part was not drawing the boxes or checking the answer. It was deciding which clues should appear first. If the first clue is too specific, experienced fans solve every round immediately. If it is too vague, the round feels random rather than challenging.

Start broad, then narrow the search space

The most reliable order in my tests was position or era first, then team history, jersey information, and finally a strong statistical or biographical clue. This lets a player build a shortlist instead of waiting for one giveaway fact. The interface should also explain whether a clue describes a current team, a career total, or a single season. That small label prevents a surprising amount of confusion.

Example clue ladder
  1. Role: guard or wing
  2. Conference and era
  3. Teams represented
  4. Jersey number range
  5. One distinctive career milestone

Fairness matters more than raw difficulty

A hard round can still feel fair when every clue points in the same direction. A round feels unfair when the data mixes seasons or changes definitions halfway through. I now validate each player record before it enters the candidate pool and keep the accepted answer names separate from the displayed label. That makes nicknames and accents easier to handle without weakening the game.

Replay loops should stay lightweight

For a daily game, the useful result screen is short: answer, attempt count, a compact clue trail, and a share action that does not reveal the player. Long explanations belong below the result, not in the middle of play. I also avoid loading the full player dataset before the first interaction when a smaller daily payload is enough.

The public reference build I use for these tests is Basketball Wordle on Wordle Cup. It is useful for checking whether the clue sequence still makes sense on both desktop and mobile.

What I would test next

The next useful experiment is adaptive hint timing. A new player may need a stronger third clue, while a regular player may prefer the same clue later. I would keep the answer pool identical and only change reveal timing, then compare completion rate, abandoned rounds, and repeat play. That keeps the test about clue presentation rather than player selection.
